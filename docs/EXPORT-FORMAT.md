# 手动导出格式（推荐先走这条路）

> 为什么推荐：沙箱里拿不到解密密钥（当前进程是 **Low 完整性级别**，读不了 Medium IL 的微信进程内存），
> 但你可以把群聊消息复制出来。这条路**零权限、零 ToS 风险、零误发可能**，
> 而且闸门、策略、双哨兵保护全都照常生效。

## 一、怎么导出（步骤以你的微信客户端菜单为准）

1. 打开目标群 → 选中要总结的消息（右键 → 多选，或长按多选）。
2. 复制，或「合并转发」到**文件传输助手**。
3. 在电脑微信里把内容复制出来，按下面格式存成文件。

手机端同样可以：长按多选 → 转发给文件传输助手 → 电脑微信打开复制。

## 二、目录结构

```
<exportRoot>/
  prod-review/                 ← 目录名随便取，建议拼音/英文
    room.json                  ← 必须：声明这是什么会话
    messages.txt               ← 必须：消息正文
  someone/
    room.json
    messages.jsonl             ← 也可以用 JSONL
```

引擎会扫描 `exportRoot` 下**每一个带 `room.json` 的子目录**，其余目录自动忽略。

## 三、room.json

```json
{
  "name": "产品评审群",
  "kind": "group",
  "id": "prod-review"
}
```

| 字段 | 说明 |
|---|---|
| `name` | 显示名，只用于报告，可以不真实 |
| `kind` | `group` / `private` / `excluded`。**这是权威声明**，引擎不从内容猜 |
| `id` | 字母数字下划线，**不能带路径分隔符**（会被拒绝，防目录穿越） |

`kind` 怎么起作用：

- `group` → 默认**可读**
- `private` → 默认**被闸门拒绝**。你把私聊目录放进来也不会被读——这正是设计意图
- `excluded` → 恒拒绝（公众号、系统号一类）

引擎会把 `id` 合成形态合法的会话 id（群 → `<id>@chatroom`，其它 → `wxid_<id>`），
再交给闸门做统一裁决，所以**换成文件源，保护逻辑一行没改**。

## 四、messages.txt 格式

```
[2026-11-10 09:12] 小王: 周五前把评审稿交上来
[2026-11-10 09:15] 老李: 待办：确认服务器预算，截止周三
[2026-11-10 09:20] 小张: @小王 数据口径按上周定的来
```

- 每行一条消息，`[时间] 发送人: 内容`
- 不匹配这个格式的行**不会丢**，会整行当成正文（只是没有发送人和时间）

## 五、messages.jsonl 格式（可选，更适合程序导出）

```
{"at":"2026-11-10T09:12:00+08:00","sender":"小王","text":"周五前把评审稿交上来"}
{"at":"2026-11-10T09:15:00+08:00","sender":"老李","text":"待办：确认服务器预算，截止周三"}
```

## 六、跑起来

```bash
WECHAT_DIGEST_SOURCE=file \
WECHAT_DIGEST_EXPORT_DIR="<项目目录>/samples/export-template" \
node src/mcp-server.js
```

或者直接看结果：

```bash
node scripts/file-demo.mjs "<项目目录>/samples/export-template"
```

## 七、两个必须知道的行为

1. **文件模式是全量快照。** 每次读都是完整一份，因此**不用增量水位线**——
   否则第二次跑会把整份导出当成"已摘要过"而全部跳过。
2. **摘要是本地关键词规则，不是模型。** 目前识别「待办/截止/开会/对齐/@」一类信号。
   要更聪明的摘要，下一步把 `summarize` 换成模型调用即可，接口已留好。
