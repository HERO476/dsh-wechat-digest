# 二期：真实取数的前置条件（需你书面授权）

本文只描述**需要什么**，不代表已经做。当前代码里没有任何解密实现、没有任何进程内存读取。

## 一、为什么现在读不到

| 事实 | 影响 |
|---|---|
| 微信 4.x 的库是 SQLCipher 变体加密（无 `SQLite format 3` 魔数，首 16 字节是盐） | 不解决解密就拿不到消息 |
| 解密密钥只在 `Weixin.exe` 进程内存里，随进程存在 | 微信必须正在运行，且要能读它的内存 |
| DSH 工作区带 `Low Mandatory Level` 完整性标签 | 沙箱内进程是 Low IL，**无法读取 Medium IL 的微信进程内存** |
| 数据目录 ACL 是 `BUILTIN\Users:(I)(RX)` | 沙箱**能读密文**，但读不出明文——所以"靠文件权限"根本不是防线 |

结论：解密能力必须来自**沙箱外、以你的用户身份、通常需要管理员权限**的组件。

## 二、授权前你必须接受的代价（如实列出）

1. **需要读 `Weixin.exe` 进程内存**才能取密钥。这在技术上等同于对微信做内存扫描。
2. **需要管理员权限**（或至少能把组件以 Medium/High IL 跑起来）。
3. **需要你在场**：微信必须已登录并运行，组件不在时插件只能 fail-closed。
4. **ToS 与账号风险未经评估**。评审团三位专家均明确表示超出角色范围、未做判断。我只能说：这类工具在公开项目里大量存在（如 `wechat-decrypt`、`weixin-decrypte-script` 一类），但这**不等于**腾讯认可，也**不能**推出"不会封号"。这一点需要你自己判断并承担。
5. **微信升级会随时打断**：做的是内存偏移与库结构适配，客户端一升级就可能失效，必须 fail-closed 而不是退化。

## 三、动手前需要你回答的三件事

1. **哪个账号**？本机 `xwechat_files` 下有两个 `wxid_*` 目录：`wxid_xxxxxxxxxxxxxxxx_aaaa`、`wxid_yyyyyyyyyyyyyyyy_bbbb`。
   插件当前设计为"必须显式绑定唯一账号，候选多于一个直接 `ACCOUNT_AMBIGUOUS` 拒绝"，所以这个必须由你指定。
2. **是否接受沙箱外 + 管理员权限**的组件？不接受则真实取数无法进行，插件只能停留在假数据模式。
3. **接受哪种口径**：`私聊正文零解析/零落盘/零进模型`（元数据可能被页级触及）——你已确认接受这一条。

## 四、已就位的接口契约

真实取数一旦接入，只需要实现适配器的两个方法，其余全部逻辑（策略、闸门、单漏斗、水位线、存储拒绝、双哨兵）不改一行：

```js
// src/adapters/wechat.js
async listRooms()      // → [{ rawId, name, authoritativeKind: 'group'|'private'|'excluded' }]
async fetchMessages({ room, fromSeq })  // → [{ seq, at, sender, text }]，只要 fromSeq 之后的增量
```

两条硬要求：

- `authoritativeKind` **必须来自存储层的权威字段**，不能来自 chat id 字符串猜后缀——闸门会用它与声明形态交叉校验，不一致即拒。
- `rawId` 必须是原始会话 id（闸门要用它算句柄），但**它不会离开闸门**。

## 五、实现顺序建议

1. 先做只读探测：确认版本、库布局、能否取到密钥（`node scripts/preflight.mjs` 已有骨架，只读、不解密）。
2. 取数只允许 `SELECT`，且必须带群维谓词；**禁止把整库解密后落盘**。
3. 第一次真实运行必须做双哨兵：你在一目标群发一条唯一口令，在一私聊发另一条，跑完断言「群的命中、私聊的零出现」。
4. 之后再接摘要模型、定时任务、UI。

## 六、已就位的下一步工具（不需要解密即可用）

### 1. 解密本身：不由本项目实现

沙箱内取不到密钥（Low IL 读不了 Medium IL 进程内存，已实测确认）。
解密这一步请用你信任的成熟工具，在你自己的常规 PowerShell 里跑，不要在这个沙箱里跑。
公开实现有多个（如 `pywxdump`、`wechat-decrypt`、`weixin-decrypte-script` 一类），
它们的工作原理都是扫描 `Weixin.exe` 进程内存取 SQLCipher 密钥。

**我没有验证过任何一个具体项目的可用性与安全性**，也没有评估其对腾讯 ToS 的影响。
选哪个、要不要用，由你判断。

### 2. 拿到解密库之后：先看 schema，别猜

```bash
node scripts/inspect-db.mjs <解密后的 message_0.db>
```

它会打印每张表的 `行数` 与 `列名`。**这是关键一步**——公开资料对 4.x 的列名说法不一，
而密文库看不到。把输出发我，我按真实 schema 写「解密库 → 本项目导出格式」的转换器，
之后整个插件就可以直接吃真实数据，不需要再改任何保护逻辑。

该脚本已用 `node:sqlite` 实现并有测试覆盖（能读表名、行数、列名，只读打开、文件不存在时明确报错）。
